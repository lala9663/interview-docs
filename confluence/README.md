## 시스템 구성

### 1. 과제 요약

면접관이 면접 전·중·후에 AI의 도움을 받는 웹 서비스다. 합격 여부는 사람이 정하고 AI의 결과는 모두 참고용이다.

![과제 요약](images/1-01.png)

### 2. Overall 아키텍처

화면 · 백엔드 · Agent 세 서비스다. DB는 백엔드만 만지고, AI는 Agent만 부른다. 신입(대면)과 경력(화상)이 같은 구성을 쓴다.

![Overall 아키텍처](images/1-02.png)

### 3. 구성요소 · 통신

통신 길은 다섯 가지이고, 길마다 인증 방식이 정해져 있다.

![구성요소 · 통신](images/1-03.png)

### 4. 주요 기능 영역

면접 전 · 중 · 후의 면접관 화면과, 채용 담당자가 쓰는 관리 화면으로 나뉜다.

![주요 기능 영역](images/1-04.png)

### 5. 설계 원칙

바꿔 끼우기 쉽게, 면접이 멈추지 않게, 사람이 판단하게 만든다.

![설계 원칙](images/1-05.png)


## 처리 흐름 · 구조 통합본

### 1. 면접 진행 흐름

엑셀을 올리는 것부터 면접관이 평가를 내는 것까지 한 줄로 이어진다.

![면접 진행 흐름](images/2-01.png)

### 2. 레이어드 구조

세 서비스 모두 기능 단위로 폴더를 나누고, 그 안에서 위에서 아래로만 부른다.

![레이어드 구조](images/2-02.png)

### 3. AI 처리 구성

AI 작업은 다섯 가지 그래프로 나뉘고, 빠른 모델과 품질 모델을 일에 따라 나눠 쓴다.

![AI 처리 구성](images/2-03.png)

### 4. Deep Agent 구조 (제안)

지금은 순서가 정해진 그래프다. 에이전트가 스스로 계획을 세우고 하위 에이전트에 일을 나눠 맡기는 구조를 제안한다.

![Deep Agent 구조](images/2-04.png)

### 5. 질문 추천 상세 과정

JD와 질문 은행에서 직무 질문을, 이력서에서 경험 질문을 만들고 금지 항목을 걸러 낸다.

![질문 추천 상세 과정](images/2-05.png)

### 6. 브리핑 생성 상세 과정

면접관 매칭이 끝나면 사전 리포트(브리핑) 작업이 자동으로 걸리고, 다 되면 화면에 나타난다.

![브리핑 생성 상세 과정](images/2-06.png)

### 7. 꼬리질문 흐름

지원자의 답이 끝나고 잠깐 조용하면, 방금 한 답을 더 깊이 묻는 질문 2~3개를 제안한다.

![꼬리질문 흐름](images/2-07.png)

### 8. JD 기반 분석

JD를 따로 분석하는 단계는 없고, JD 글을 각 AI 작업의 재료로 넣는다. 쓰이는 곳은 다섯 군데다.

![JD 기반 분석](images/2-08.png)

### 9. 턴 디텍션 · 의도 분석

말의 끝은 침묵으로 잡고, 누가 무엇을 말했는지는 글 내용으로 판정한다. 의도 분류 모델은 따로 없다.

![턴 디텍션 · 의도 분석](images/2-09.png)

### 10. 음성 스트림 처리

SSE가 아니라 WebSocket을 쓴다. 음성을 올리고 결과를 내려받는 일을 연결 하나로 하기 때문이다.

![음성 스트림 처리](images/2-10.png)

### 11. 스트림 서버 분리 여부

지금은 나누지 않는다. Agent를 여러 대로 늘리는 것으로 먼저 대응하고, 사내 AI로 부하를 잰 뒤 다시 판단한다.

![스트림 서버 분리 여부](images/2-11.png)

### 12. 분리 구성 · 판단 기준 (제안)

나눌 때의 구성과, 나눌지 말지를 정할 때 볼 네 가지 숫자를 정리했다.

![분리 구성 · 판단 기준](images/2-12.png)

### 13. LLM 속도 개선 방안

면접 흐름이 멈추지 않는 것이 우선이다. 이미 넣은 것 다섯 가지와 사내 모델을 붙인 뒤 검토할 것 네 가지다.

![LLM 속도 개선 방안](images/2-13.png)

### 14. 질문 페르소나 설정 (제안)

지금은 면접 종류와 상관없이 같은 말투로 질문을 만든다. 면접 종류마다 면접관의 관점을 정해 주는 것을 제안한다.

![질문 페르소나 설정](images/2-14.png)

### 15. 기술 스택

사내에 인터넷이 없어, 모든 라이브러리를 사내 미러에서 받을 수 있는 것으로만 골랐다.

![기술 스택](images/2-15.png)


## 다시 만드는 법

1. `source/gen.py`에서 글을 고친다. 항목 하나가 `page(...)` 한 덩어리다.
2. `python source/gen.py <임시 폴더>`로 항목마다 HTML을 만든다.
3. 크롬으로 각 HTML을 1600×900 PNG로 찍는다: `chrome --headless=new --window-size=1600,900 --screenshot=<파일>.png file:///<임시 폴더>/<항목>.html`
4. PNG를 `images/`에 같은 이름으로 덮어쓴다.
5. PPT도 다시 만들려면: `BODY_ONLY=1 python source/gen.py <임시 폴더>`로 그림 부분만 만들어 1600×640으로 찍고, `node source/build_ppt.js <임시 폴더> <출력.pptx> <apply_theme.js 경로>`를 돌린다(`pptxgenjs` 필요).
